# Audit + refactor recommendations — v0.8.0a36

Written after the v0.8.0a36 sweep that fixed the catastrophic
merged-tree state reported by the user (three duplicate "MSOffice"
top-level folders, self-referencing circular reference, no way to
right-click the column header for Save, Save All not propagating to
sources).  This doc captures what's brittle, what's grown beyond its
original design, and what the next maintainer should consider
refactoring.

The recommendations are **not** TODOs to action now — they're the
"if you had a free afternoon" list.

---

## What changed in v0.8.0a36 (context for the audit)

| Surface | Change | Rationale |
|---|---|---|
| `scriptree/shell/merged_tree.py` | De-dup by display name with `(parent-folder)` then `(N)` disambiguation. | Two source `.scriptreetree` files both internally named "MSOffice" produced two indistinguishable top-level folders. |
| `scriptree/shell/merged_tree.py` | `_inline_subtree_refs` -- subtree references are now expanded INLINE at build time, not at view time. | Pre-a36 the inline content was read-only because it belonged to a different file.  User couldn't drag/delete the duplicates to repair. |
| `scriptree/ui/tree_view.py` | Wire `header().customContextMenuRequested` to the same context-menu handler. | User naturally right-clicks the "Tools" column header expecting Save; that was a dead zone. |
| `scriptree/ui/main_window.py` | `_collect_unsaved_items` tree save now also runs `push_back_to_origins` when the saved file is a merged tree. | Save All wrote the temp file but not the originating source files. |

8 new unhappy-path tests in `tests/test_editor_unhappy_paths_a36.py`.

## Refactor recommendations

### 1. Extract a `MergedTreeSession` class

**Problem.**  `scriptree/shell/merged_tree.py` has grown from a small
"build a temp tree" helper to a full lifecycle manager:

* Build the merged tree from sources.
* Write an origins sidecar.
* De-dup + disambiguate display names.
* Inline subtree refs (recursive, cycle-aware).
* Push-back on save with leaf-path canonicalisation.
* Sweep stale temp files on every build.

That's six responsibilities in nine free functions sharing module-
level state (the `_MERGED_PREFIX`, `_ORIGINS_SUFFIX`,
`_MERGED_STALE_SECONDS` constants and a cache attribute attached to
the master cell).  A `MergedTreeSession` class owning the temp path,
sidecar, source set, and `push_back()` method would centralise the
contract.

**Sketch:**
```python
class MergedTreeSession:
    def __init__(self, sources: list[Path]) -> None: ...
    @classmethod
    def for_master(cls, master) -> "MergedTreeSession": ...
    @property
    def path(self) -> Path: ...
    def push_back(self) -> PushBackResult: ...
    def cleanup(self) -> None: ...
```

**Risk.**  Existing callers (`shell.v1_launcher.show_composite_for`,
`ui.main_window._save_tree`) all use the free-function API.  A
migration would touch three call sites; do this as a pure refactor
with the test suite already in place to catch breakage.

### 2. Extract the uninstall dialog

**Problem.**  Two surfaces show identical "Uninstall app from disk..."
dialogs with keep-local + keep-shared checkboxes:

* `scriptree/shell/forest_controller.py::ForestController._on_uninstall_app`
  -- the cell-popup right-click path.
* `scriptree/ui/main_window.py::MainWindow._on_tree_uninstall_requested`
  -- the editor's tree-view right-click path (added in a34).

The dialog construction is **copy-pasted** between the two -- 60+
lines of QDialog + checkbox + button setup duplicated.  When the
user later asks "add a third checkbox," we'll have to update both
sites.

**Fix.**  Move the dialog into
`scriptree/shell/forest_dialogs.py::UninstallAppDialog`.  Both
surfaces import + show it.  The cell-popup side already lives in
`shell/`; the editor side needs to import across the shell boundary
(which is fine -- shell already depends on ui via the V1 launcher
path).

### 3. V1 tree_view.py is over a thousand lines

**Problem.**  `scriptree/ui/tree_view.py` is 1287 lines and now
owns: `_EditableTreeWidget` (drag/drop + right-click handling),
`TreeLauncherView` (the public widget), the subtree expansion logic,
the save/save-as machinery, the dirty-state tracking, the recovery
dialog, the toolbar, and the icon resolution.

Some of these have natural seams:

* Subtree expansion (`_expand_subtree`, `_expanding_paths`,
  `(circular reference)` rendering) -- could move to a
  `tree_subtree.py` helper.  Now that merged-tree builds inline
  subtrees at build time (a36), the view-time subtree logic is
  mostly used by NON-merged trees (the editor opened directly on
  a `.scriptreetree`).
* The recovery dialog (`_offer_missing_tool_recovery`,
  `recovery_dialog.py` integration) -- could collapse.
* Icon resolution (`_node_icon`, the bundled-icon lookup) -- the
  cell shell has a parallel resolver; share.

**Risk.**  Moderate.  Tests for the tree view are scattered; need
to run the full ui/ test band after each extraction.

### 4. Remove vestigial save QActions

**Problem.**  `MainWindow._build_menu` still creates
`self._act_save_tool`, `self._act_save_tool_as`, `self._act_save_tree`,
`self._act_save_tree_as`, `self._act_save_cell_layout`,
`self._act_save_cell_layout_as` -- six QActions kept ONLY for
back-compat with code that reads their `.isEnabled()` state.  They
are not added to the visible File menu (a33+).

The state-tracking calls (`self._act_save_tool.setEnabled(False)`
in `_on_tree_modified`, etc.) could move into a `_save_state`
ad-hoc dict on the instance.  The QAction objects are heavyweight
for what amounts to a boolean.

**Risk.**  Low; constants of grep'able names.

### 5. `_persist_uninstall_to_forest_file` belongs on ForestController

**Problem.**  v0.8.0a35 added
`MainWindow._persist_uninstall_to_forest_file(catalog_path)` to
update the on-disk `.scriptreeforest` after an editor-side
uninstall.  This is forest-state logic, but it lives in `ui/`
because that's where the call site is.

**Fix.**  Move to `ForestController.persist_uninstall_to_file` as
a classmethod.  Editor calls `ForestController.persist_uninstall_to_file(catalog_path)`.
Lives next to the sibling `uninstall_app` it complements.

### 6. Bare `except` everywhere

**Problem.**  Pervasive `except Exception:  # noqa: BLE001`
swallows.  Acceptable in true rescue paths (UI never crashes),
but the `# noqa: BLE001` is a paper-cut every grep across the
codebase.  Counting: 200+ instances.

**Fix.**  Sweep to convert at least the obvious cases to typed
exceptions (`OSError`, `json.JSONDecodeError`, etc.).  Leave the
genuine "the UI must never crash" rescues as-is with a deliberate
comment explaining why.  The auto-dismiss-QMessageBox lesson
(`rags/lessons/auto_dismiss_qmessagebox_in_tests.md`) explains
the test-side counter-pattern.

### 7. No end-to-end smoke test for forest -> editor -> save

**Problem.**  We have unit tests for each piece (merged_tree,
push_back, tree_view, main_window) but no test that exercises
the full flow: forest with members -> double-right-click ->
editor opens on merged tree -> edit -> save -> sources updated
-> forest re-reads -> changes visible.

**Fix.**  `tests/test_forest_editor_e2e.py` with a single
roundtrip test using `tmp_path` for the entire workspace.  Mocks
subprocess.Popen so V1 doesn't actually spawn.

## Comment / doc audit findings

Performed on files touched in v0.8.0a31-a36 (the merged-tree +
editor work).

### Stale comments

* `scriptree/ui/tree_view.py:36-38` -- comment says "Activation is
  ``itemClicked`` (single click on a leaf), NOT
  ``itemDoubleClicked``... do not rewire ``_on_item_activated`` to
  double-click".  v0.8.0a35 changed the consumer side
  (`_on_tool_selected` is now a no-op) but left this comment in
  place.  The comment is misleading without context.  **Action:**
  add a v0.8.0a35 addendum noting that the launcher still emits
  ``toolSelected`` but the editor no-ops on it.
* `scriptree/shell/v1_launcher.py:35-49` -- the docstring section
  on DETACHED_PROCESS still references it as the historical flag
  even though v0.8.0a29's no_console_popen_kwargs sweep replaced
  it.  **Action:** cross-reference the v0.8.0a29 lesson.

### Out-of-date docs

* `docs/cell_shell.md` -- still describes the editor's File menu
  with six save items.  v0.8.0a33 consolidated to three.
  **Action:** update the menu screenshot description.
* `docs/LLM/architecture.md` -- no section on the merged-tree
  back-propagation pipeline.  **Action:** add one.

### Documentation gaps

* `docs/LLM/scriptreering_format.md` covers the ring format but
  there's no doc for the `.origins.json` sidecar shape that
  `merged_tree.py` writes.  **Action:** add a 1-page format
  reference.
* The "what does single-click do in V1's editor" semantic has
  shifted multiple times across releases.  **Action:** add a
  short "editor UX gestures" section to `docs/cell_shell.md`.

## What worked well (keep doing it)

* **Failing tests first.**  Every fix in this sweep started with
  a test that captured the bug, then the code change made it
  pass.  7 → 0 failing across two sweeps (a35 + a36).
* **Backup before sweeps.**  Pre-a35 and pre-a36 backups gave us
  insurance that wasn't needed but would have saved hours if
  any of these merged-tree changes had corrupted a real
  catalog.
* **Hash-verify R: after every deploy.**  Caught the a25 -> a28
  "wrong file was being bumped" gap (see
  `rags/lessons/version_lives_in_two_files.md`) immediately
  on the first user report.
* **Lessons file per discrete finding.**  The `rags/lessons/`
  directory now has 56 entries; the cross-referencing between
  them is what makes the next session start smarter than the
  last.
